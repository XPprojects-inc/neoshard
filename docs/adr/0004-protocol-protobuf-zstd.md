# ADR-0004: Протокол — Protobuf поверх WebSocket, zstd, спецификация в spec/
- Статус: принято · 2026-10-18
## Контекст
JSON+zlib тяжелее по CPU и трафику; бинарный формат с кодогенерацией даёт сторонним клиентам типы на любом языке.
## Решение
- `spec/proto/*.proto` — источник истины; `neoshard-proto` генерирует Rust через `prost-build` + `protox`
  (чистый Rust-компилятор proto — не нужен системный `protoc`).
- Каждый WS-фрейм — бинарный `GatewayFrame`. `?compress=zstd` → каждый фрейм сжимается отдельно (уровень 3).
  Потоковый контекст отвергнут: ломает resume на другом узле и усложняет сторонние клиенты.
- REST — JSON (OpenAPI 3.1) ради простоты ботов на curl; ID в JSON — строки.
- Версионирование: `/api/v1`, `/gateway?v=1`. В мажорной версии — только добавление полей/событий;
  удаление — через deprecation минимум 6 месяцев. Неизвестные события клиент обязан игнорировать.
