# ADR-0019: E2EE в потоке сообщений и отдельная WASM-сборка с MLS
- Статус: принято · 2026-10-19
- Связано: ADR-0013 (MLS), ADR-0009 (граница ядро ↔ UI)

## Контекст
MLS-примитивы были в ядре, но `SendMessage` в e2ee-канале не шифровал, ключи жили только в памяти.
Ядро с openmls весит 437 КБ gzip — больше бюджета 400 КБ, а без MLS — 149 КБ.

## Решение
1. **Шифрование целиком в ядре** (`crates/neoshard-core/src/e2ee_flow.rs`). UI шлёт обычный
   `SendMessage` и получает расшифрованные события, ключи и шифротекст наружу не выходят.
   После Ready ядро создаёт MLS-устройство и публикует 20 KeyPackage. Первая отправка в канал
   запускает сборку группы: claim KeyPackage каждого собеседника → add → Welcome через сервер.
   Только после доставки Welcome уходят сообщения из очереди, так что Welcome всегда приходит первым.
2. **Хранение**: состояние устройства (подпись, хранилище openmls, группы) сериализуется в
   `CacheSnapshot.mls_state` — тот же офлайн-снимок (IndexedDB / SQLite / store Tauri), что и токен сессии.
   Уровень доверия одинаковый.
3. **Свои сообщения**: MLS не расшифровывает собственный шифротекст, поэтому ядро хранит открытый
   текст своих сообщений по `nonce`, а уже расшифрованных — по `id`. Каждый шифротекст
   расшифровывается ровно один раз.
4. **Две WASM-сборки**: `wasm/` (базовая, 149 КБ, бюджет 400 КБ) грузится всегда. `wasm-e2ee/` (437 КБ)
   грузится вместо неё только на устройствах, где пользователь включил «Зашифрованные ЛС».
   Базовая сборка переносит чужое `mls_state` без изменений, поэтому переключение не теряет ключи.
   Десктоп всегда собирается с `e2ee`.
5. Пара пользователей может иметь одно обычное и одно зашифрованное 1:1-ЛС (миграция 0004).

## Последствия и ограничения
- Новое устройство не читает уже созданные группы: нужен commit с добавлением устройства.
  Свои старые сообщения на другом устройстве не видны.
- Не реализованы добавление участника в существующую группу, удаление, ротация ключей (update/commit).
- Если у собеседника нет ключей (он ни разу не входил клиентом NeoShard), отправка честно падает
  с понятной ошибкой. Открытым текстом ничего не уходит.
- `neoshard-core` теперь только `rlib`: cdylib/staticlib собираются через `cargo rustc --crate-type`,
  иначе на windows-gnu тестовая DLL переполняет таблицу экспорта PE.
