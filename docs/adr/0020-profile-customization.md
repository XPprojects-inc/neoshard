# ADR-0020: Кастомизация профиля
- Статус: принято · 2026-10-19
- Связано: ADR-0013 (E2EE), ADR-0009 (граница ядро ↔ UI), `spec/profile-catalog.md`

## Контекст
Пользователи ждут привычный набор возможностей профиля:
- местоимения, «обо мне», баннер, цвет и тема карточки;
- рамка аватара, эффект профиля, табличка в списках, стиль имени, тег сервера;
- свой статус с эмодзи и сроком действия, отдельные профили на серверах, заметки, внешние ссылки.

Ограничения проекта: никаких чужих ассетов, данные не уходят третьим лицам, всё self-hosted.

## Решение
1. **Где хранятся данные.**
   - Компактная косметика (рамка, табличка, стиль имени, тег) лежит в `User` и приезжает везде, где виден пользователь.
   - Тяжёлые поля (bio, баннер, тема, ссылки, серверный профиль) отдаются по запросу `GET /users/{id}/profile`.
2. **Видимость.** Профиль видят только сам пользователь, его собеседники по ЛС и участники общих серверов. Остальные получают 404, как для несуществующего id.
3. **Каталог.** Список id лежит в `neoshard_proto::profile`. Сервер проверяет id, клиент рисует собственный SVG/CSS. Форки расширяют список, а неизвестные id клиенты игнорируют.
4. **Профиль на сервере.** Отдельные `avatar`, `banner`, `bio`, `pronouns` и `theme_colors` у участника. Пустое поле берётся из основного профиля, менять его может только сам пользователь.
5. **Тег сервера.** До 4 символов и значок задаются в `PATCH /guilds/{id}` (право MANAGE_GUILD). Пользователь выбирает, чей тег показывать. Тег виден, только пока пользователь состоит на этом сервере.
6. **Ссылки вместо «подключений».**
   - OAuth-приложения сторонних сервисов на self-hosted инстансе не настроишь, а данные уходили бы третьим лицам.
   - Поэтому подтверждение сделано как в IndieWeb: страница должна ссылаться на профиль с `rel="me"`.
   - Сервер скачивает страницу через тот же SSRF-фильтр, что и превью ссылок.
7. **Свой статус.**
   - Текст, эмодзи и срок действия хранятся в БД и восстанавливаются при входе.
   - Собственное присутствие (в том числе «невидимка») приходит в Ready, чтобы новое устройство не затёрло статус.
   - Просроченный статус не показывается.
8. **Файлы без S3.**
   - `NEOSHARD_FILES_DIR` даёт подписанный PUT (подпись связывает ключ, срок, размер и тип) и раздачу `/files/*`.
   - Inline отдаются только картинки, остальное — как скачиваемый файл; CSP `sandbox`, `nosniff`.
   - Клиент строит URL как `Ready.files_base + "/" + key`.

## Последствия
- Удаление аккаунта стирает все новые поля, ссылки и заметки.
- Смена тега сервера не рассылает `UserUpdate` каждому участнику: клиенты сами обновляют теги по `GuildUpdate`.
- Нет магазина и платных предметов. Анимированные аватары возможны (GIF), но не перекодируются.
