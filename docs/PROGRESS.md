## Что не сделано / ограничения (в порядке важности)

1. **E2EE — ограничения первой версии** (ADR-0019). Работает: шифрование в ядре, хранение ключей, 1:1 и групповые ЛС. Не сделано:
   - добавление участника или устройства в существующую группу (новое устройство не читает старые беседы);
   - удаление участника и ротация ключей;
   - свои сообщения на другом устройстве не видны.
2. **Медиа**: RNNoise из ядра не встроен в веб-захват (используется браузерный noiseSuppression). TURN через coturn не проверялся: локально хватило host-кандидатов. Захват микрофона и камеры из браузера не проверялся — панель браузера блокирует устройства; публикация проверена через Node SDK, приём — в браузере.
3. **Push-уведомления**: подписки хранятся, отправка Web Push (VAPID, RFC 8291) не реализована.
4. **UI**: нет интерфейса управления ботами и slash-командами (есть в API). Стикеры — только картинки (Lottie не рисуем). Вложения в E2EE-беседах шифруются на устройстве, но их превью не генерируются (картинка показывается после расшифровки).
5. **Часть проекции состояния в TS** дублирует логику ядра (порядок сообщений, счётчики реакций, непрочитанное) — по замечанию ревью; план — ядро отдаёт нормализованные view-дельты.
6. **Федерация**: только идентичности и ЛС; федерация гильдий — в спецификации как roadmap.
7. **Кластер**: шина NATS реализована (feature `nats`), но presence/voice — в памяти узла (нужен Valkey для нескольких узлов); не тестировалось в кластере.
8. **Восстановление пароля**: письма — только через свой SMTP, не проверено e2e.
9. **Десктоп-RAM** выше цели (см. бюджеты).
10. **Android** (`apps/android`, Tauri 2 mobile, нативное ядро; на узком экране — Material-раскладка). APK собирается и подписывается.
    - Проверено в эмуляторе (Android 16, x86_64): вход тестовым аккаунтом через `adb reverse`, главный экран, отступы под системные панели.
    - Команды ядру на Android идут через postMessage (Tauri не читает тело запроса в custom protocol); `core_dispatch` принимает и сырые байты, и JSON-массив.
    - Голос и звонки с микрофоном и камерой: разрешения объявлены в манифесте, система спрашивает их при первом звонке (проверено в эмуляторе: трек микрофона доходит до LiveKit).
    - Сервер на этом же устройстве (`localhost`, `adb reverse`) работает без TLS; любые другие серверы — только по HTTPS.
    - Нет push-уведомлений.
    - Картинки грузятся только с HTTPS-сервера.
    - iOS не собирался: нужен macOS.
11. **Звонки в ЛС**: рассылка состояния собеседникам, окно входящего вызова с мелодией (WebAudio), блокировка останавливает звонки (тест `calls.rs`). Нет: звонков с видео по умолчанию, пропущенных звонков в истории, звука вызова, когда приложение свёрнуто на Android.
12. **Сайт** (`apps/site`) на `/`, веб-клиент на `/app/`, сборки на `/downloads/` (`publish-downloads.sh`). Маскот-пингвин анимирован (покачивание, моргание, реплики по клику). Способы пожертвований пока не настроены (`site.json`).
13. **Публичные серверы** (ADR-0022): поиск по названию и вступление без приглашения внутри одного сервера NeoShard; межсерверного каталога нет.
15. Открытые Medium/Low из security-ревью — `docs/security-review.md` (TTL голосовых токенов, лимиты федерации и числа тредов/инвайтов, MLS key-package scope и др.).

## Как продолжить

- Окружение Windows: `scripts/env.sh` (GNU-тулчейн + MSYS2 gcc), PostgreSQL из scoop
  (`pg_ctl -D ~/scoop/apps/postgresql/current/data start`), БД `neoshard/neoshard`.
- Dev: `bash scripts/dev-server.sh` + `npm run dev` → http://127.0.0.1:5173.
- Медиа: `tests/media/README.md` (LiveKit `--dev`, затем `npm test`).
- Следующие шаги: п.4 (UI) → п.3 (push) → E2EE-коммиты (добавление устройств) → прогон 100k на Linux.
